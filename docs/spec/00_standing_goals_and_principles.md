# 00 — Standing goals and principles

## Standing goals (D58) — always open, across all phases
1. **Continuous spec maintenance** at every level: project book (Hebrew page + `docs/spec/`), PRD, SRS, derived technical docs — always in sync.
2. **Ship** a first version to the Apple App Store and Google Play, run it, then continuous version updates.
3. **Quality code**: professional, efficient, modular, scalable. Every task = code + spec section + automated test.

## Product & working principles
1. Spec first, then tasks, then code.
2. **One, not many**: one `Post` entity (D2, D19); one world-hub infrastructure configured per world (D36); one karma value config (D29).
3. Each world/domain gets gentle personality via **configuration and plug-in blocks**, never duplicated code (D36).
4. Precise names in Hebrew and in code — never a bare "categories" (see [94](./94_glossary_and_naming.md)).
5. Don't rebuild what a leading nonprofit already does well — connect to it (D37).
6. The user controls (sort/filter/notifications); the system recommends (D27).
7. Only real contradictions or important questions go to the PM; other gaps are filled and tagged `S#`.
8. Technical derived docs are in English, structured for AI coding agents.
